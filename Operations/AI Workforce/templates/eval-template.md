# Eval: Agent Name

**What good looks like before this work reaches a person.**

**Owner:** the named human from the agent file
**Used by:** the editor (or the director) on every output from this agent
**Version:** 1.0, date
**Pass bar:** weighted score of 4.0 or higher, no criterion below 3, zero auto-fails

## How to score

Score each criterion 1 to 5. Write the reasoning first, then the number. If the work is missing what you need to judge it, mark "cannot assess" and escalate to the owner. Score against the bar, not against how much you like the draft.

## Criteria

Keep to the handful that decide acceptance. Give each a weight, a description of a 5, and a description of a 1.

**1. Facts match the source (weight)**
A 5: every name, number, address, and date appears in the cited source. A 1: anything invented, estimated, or carried over from a previous run.

**2. Voice (weight)**
A 5: reads like Brett over coffee; passes every rule in voice-principles.md. A 1: banned words, fragments, staccato, filler, em dashes.

**3. Fit for the destination (weight)**
A 5: right length, format, and platform rules for where it is going. A 1: needs reformatting before it can be used.

**4. Would the stakeholder say yes (weight)**
A 5: the list-side producer, the brokerage owner, and Elizabeth as operator would each accept it. A 1: one of them rejects it outright.

**5. Complete and labeled (weight)**
A 5: every requested output present and labeled by destination. A 1: pieces missing or unlabeled.

**For a skill, add one criterion: fires on five phrasings that should trigger it and stays quiet on three that should not.** Score the description, not the output.

## Automatic fails

- Any fact not traceable to a source
- Any em dash
- Anything sent, posted, or written to a live system by the agent itself
- Personal or compensation data in a shared output

## When a human steps in

Escalate before any recommendation if a criterion scores below 3, an auto-fail triggers, or the output is client-facing and the editor is unsure.

## Keeping this eval sharp

When a human reviewer disagrees with a score, fix this document, not that one score. Every miss becomes a line in the next version. Rerun the whole eval on every model release.
