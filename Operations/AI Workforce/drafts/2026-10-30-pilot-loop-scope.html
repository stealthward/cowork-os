Pilot Loop Build

COO scope and plan, 2026-10-30. AI Workforce task "Pilot loop: the Asana project the workforce answers in" (Team launch, due 10/30).

Scope

System
One Asana project where Elizabeth posts asks for the workforce. A scheduled run reads it, answers or drafts in task comments, and acts on anything that changes something only after a like on its comment or the Approved field.
Users
Elizabeth (asker, pilot 11/9 to 11/20), you (asker and approver). The run wears the seat the ask belongs to, by the root routing map.
Source of truth
The Asana project. Run state and pilot issues in Operations/AI Workforce/logs/.
Platform
Asana connector (reads, comments), asana-specialist (read-only volume read), a desktop scheduled task on the office PC.
Done when
The project exists, the asana-specialist reads it on a schedule, its brief carries the four rules (draft never send, say what you cannot do, correct yourself out loud, report what you did not check), and one seeded low-risk ask and one seeded change ask both pass end to end.
Touches
New Asana project; asana-specialist brief and its kit copy; new skill pilot-loop; new scheduled task; registry, operations map, root MEMORY.md Scheduled Tasks table.
Conventions
asana-conventions.md (new project fields, portfolios, Elizabeth as admin, Approval signals).

Project design

NameAsk the Workforce (your call below)

CommentsPosted from your Asana account, opening "This is the COO." (or the CMO, chief of staff), per the root Asana comment rule

One run

  1. Read the state file (last run time). Dispatch the asana-specialist in a new loop mode: tasks created or changed since then, new comments, likes on the workforce's comments, Approved field values.
  2. Nothing new: log one line and stop.
  3. New ask: classify it. Low-risk (a question, a read, a draft): do it and reply. Changes something: reply with exactly what it would do, move the task to Waiting on your approval.
  4. Approved (like or field): do the staged change, reply with what was done and what was not checked, move to Done.
  5. Can't do it (out of lane, Max Income, sending, spending): say so in the reply and name who can.
  6. Log the run; log any pilot issue to pilot-issues.md for kit fixes (roadmap Phase 4 step 4).

Plan

  1. Registry rows for the pilot-loop skill and scheduled task (the registry hook blocks a skill with no row). COO, no specialist.
  2. Create the project, sections, fields, and How to ask task through the connector. Approved field, Elizabeth's admin role, and portfolios in the built-in browser if the connector can't. COO.
  3. asana-specialist: add Loop mode and the four rules; same edit to the team-kit copy. COO.
  4. Write .claude/skills/pilot-loop/SKILL.md and the state and log files. COO.
  5. Seeded test: I add one question and one change ask, run the skill by hand, check the replies, you like the change reply, I confirm it acted. Test tasks deleted on your yes.
  6. Create the scheduled task; add Asana allow rules to ~/.claude/settings.json so unattended runs do not stall.
  7. Document: operations map, registry, root MEMORY.md Scheduled Tasks table, asana-specialist eval line. Complete the Asana task when Done when is verified.
