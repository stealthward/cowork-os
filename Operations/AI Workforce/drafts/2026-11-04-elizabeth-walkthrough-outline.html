Part 1: Ask the Workforce

1:00 to 6:00
On screen: Asana, Ask the Workforce, then the worked example task.
  • Make an ask: a new task in New asks, one ask per task, with what done looks like in the description.
  • Timing: the loop checks every 30 minutes, weekdays 7 AM to 6:30 PM. Comments she adds to an open task count as new asks.
  • The reply: a comment that opens "This is the COO." (or the CMO, or the chief of staff) and mentions her, so Asana emails her.
  • The four sections: New asks, Working, Waiting on your approval, Done.
  • Approving a change: anything that changes a system outside this project waits in "Waiting on your approval" with exactly what will change. Approve by liking the comment or setting Approved to Yes. Only her like or Brett's counts. A new comment asking for something different cancels the approval and it gets re-staged.
  • The four rules: drafts, never sends; says what it can't do; corrects itself out loud in a new comment; ends every reply with "Not checked:".
  • She closes tasks. The loop moves sections and comments; it never completes, assigns, or dates a task.
  • Out of bounds: Max Income, compensation, spending, signing, credentials. It will say so and name who can help.

Part 2: Session startup

6:00 to 11:00
On screen: Code tab on the kit folder; start one short live session.
  • Where: the Code tab in the Claude desktop app, opened on her Cowork OS folder. Workers and skills only run in Code.
  • First session only: ask Claude to fill in voice-principles.md and the "My preferences" section of CLAUDE.md. It interviews her through question boxes.
  • Every session: name the workstation in the first message, for example "Working in Operations." Claude reads the rules and memory on its own.
  • The one rule: nothing durable lives in a chat. If it matters tomorrow, it goes in a file.
  • The phrases (show the table in users-guide.md):
SayWhat happens
"Remember this: ..."Writes a fact to MEMORY.md now
"Add a rule: ..."Writes a behavior rule to CLAUDE.md now
"Resume [project]"Starts on that project's next action
"Audit this session"Saves what the thread decided before you close it
"Handoff"Audits, then writes what is unfinished so the next session picks it up
  • Ending: "audit this session" every time; "handoff" if the work is not finished. One job per thread.
