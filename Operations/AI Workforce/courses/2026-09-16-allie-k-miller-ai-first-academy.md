## Their recommended buildout

One human talks to one agent. A chief of staff on the strongest model routes every request to named directors, one per lane, running on a mid-sized model. Each director owns three to six unnamed single-purpose sidekicks on the smallest model, and any director can spin up temporary agents for one task. A dedicated assistant to the chief of staff curates what the system learns. Everything is plain markdown on disk: an instructions file the harness reads at session start, one agent file per agent with model and tools set at the top, skill folders, memory files, evals, and a set of shared state documents. Agents run on three kinds of triggers (clock, event, heartbeat), a second agent judges output against a written bar before a person sees it, and the team reaches the workforce through a shared channel the agents check every fifteen to thirty minutes. Governance is a checklist: named owner, least privilege, right-sized model, clear role, inventory, audit trail, removal mechanism, human gates, eval.

## Adopt

- **Six-tier workforce shape, mapped to the OS.** Chief of staff at the root, directors as workstations, sidekicks per lane, temps for fan-out. Lands in Phase 2 (first director and its sidekicks) and Phase 3 (chief of staff once two lanes exist).
- **Discovery-first, plan-first, build-last.** Before writing any agent, run a discovery pass over the OS (root and workstation memory, Asana priorities) and return a roster and file plan for approval. Nothing gets written until Brett approves the roster. Lands at the start of Phase 2, adapted to our folder rather than copied.
- **Agent file template.** Name, when to use it, model and tools in the settings block; then owner, the one lane it owns and what it never touches, trigger, definition of good with source and timestamp on every figure, work log location, kill switch. Lands in Phase 2 as the template every agent is written from.
- **Eval file next to every agent.** A handful of criteria that decide acceptance, weighted, with auto-fails and an escalation rule. When a human disagrees with a score, fix the eval, not the score. Lands in Phase 2; the Editor grades against it.
- **Usage log.** Every agent appends one line per run: date, agent, one-line summary. Feeds the 90-day kill-or-promote review and the Phase 3 dashboard. Lands in Phase 2 as a file in the AI Workforce folder.
- **Autonomy-boundaries file.** One page: what agents may do without asking (draft, research, update state) and what always waits for Brett (send, spend, sign, reply to a client, change a live system). Cascades to every director and sidekick. Lands in Phase 2 at the OS root next to the agent files.
- **Lane discipline written into both sides of an overlap.** Content and Business Development overlap on REACH promotion and the partner campaign; write the handoff into both director files. Lands in Phase 2 when the second lane exists.
- **A/B/C task tracker per lane.** List every task in the lane, test against the current model, sort into hand it off, work alongside, keep it. Retest when a new model ships. Lands in Phase 1 as the intake step for each lane, starting with content operations.
- **De-risk checklist in the agent template.** Checkpoints inside the workflow, fallback decided before failure, ceiling on what an unsupervised run may do, validation as part of the job. Lands in Phase 2.
- **Mission control rendered from roster plus usage log.** Lands in Phase 3; confirms the design already in roadmap.md.
- **Loop channel with the four trust rules.** Elizabeth's pilot gets a channel (Asana project or email, Slack if the team uses it) the workforce checks every fifteen to thirty minutes. Lands in Phase 4.
- **Second skill that reviews the first.** Stakeholder-persona reviewer built from the people who have to say yes: for content, the $50M+ list-side producer, the brokerage owner, Elizabeth as the operator. Lands in Phase 2 alongside the Editor.
- **Eight Asks.** Disagree with me, poke holes, three perspectives, clarifying questions first, failure modes and blockers, synthetic users, more unexpected, more actionable paths. Lands in the Editor's eval and the Brand Driver skill.
- **System improver role.** A dedicated assistant to the chief of staff that tracks projects, finds weak spots, and curates memory. Lands in Phase 3 once there is a workforce to improve.

## Reject or defer

- **Agents under the user-level `~/.claude/agents/` folder.** Her build puts every agent in the personal home folder. Ours go in `.claude/agents/` at the Cowork OS root so they ship with the Shared Core. Reason: team deployment.
- **Build the whole workforce at once with a meta-agent.** Defer. We build one lane end to end first, then let discovery and the usage log grow the rest. Reason: Elizabeth's pilot needs one reliable lane more than six half-tested ones.
- **"End every response with three to five more things I could take off your plate."** Adapt rather than adopt. It conflicts with Brett's under-300-words rule and no-weak-closers rule. Give it to the chief of staff as a weekly report line instead of every response.
- **Daily AI diary popup.** Defer. "Audit this session" plus the memory files cover the same need. Revisit if a dictated daily note would feed the content lane (it might: ideas for authority content).
- **"Do smart things" scheduled prompt to the whole org.** Defer to Phase 3 or later. Needs a workforce, an autonomy file, and a usage log before it is safe or useful.
- **Codex live voice mode, Remote Control, Make.com flows, Manus, NotebookLM, Synthesia.** Reject. Other tools, off-goal.
- **Notion as the SOP library.** Reject. The OS folder and Google Drive are the shelf.
- **Claude Tag in Slack.** Hold until Brett confirms whether the team lives in Slack. If not, the email or Asana loop is the on-ramp.
