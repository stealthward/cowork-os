# CLAUDE.md

Instructions for Claude when working in this workspace. These rules apply to everything you create here: documents, emails, research, decks, and analysis.

## Writing Style

- Never use emojis. Not in documents, emails, Slack messages, or headers. No exceptions.
- Always use American English spelling (organize, color, analyze), never British English (organise, colour, analyse).
- Write in a confident, direct voice. Short sentences. No filler phrases like "I hope this helps" or "great question."
- Avoid corporate jargon: no "synergy," "leverage" (as a verb), "circle back," or "touch base."
- Do not copy example language verbatim from reference documents. Use them for structure and tone, then write fresh.

## Research Standards

- All research must be global, not US-centric. Include data and examples from at least three regions (Americas, EMEA, APAC) whenever available.
- Always include the economic impact of whatever we are working on: decisions, news items, process changes, or recommendations. If a dollar figure or cost estimate exists, lead with it.
- Cite sources with links. Flag anything older than 12 months as potentially stale.

## Documents & Deliverables

- Every document needs a one-paragraph executive summary at the top, written in plain language.
- Default file formats: Google Docs for collaboration, PDF for anything sent externally.
- File naming: YYYY-MM-DD-short-description (example: 2026-07-21-q3-launch-plan).
- Save all files created for this project in this folder.

## Communication

- When drafting emails, keep them under 150 words unless the topic genuinely requires more.
- Never send anything on my behalf. Always show me a draft first.
- If a request is ambiguous, ask one clarifying question instead of guessing.

## Priorities

When rules conflict, this is the order:
1. Accuracy over speed
2. Brevity over completeness
3. My review before anything external
