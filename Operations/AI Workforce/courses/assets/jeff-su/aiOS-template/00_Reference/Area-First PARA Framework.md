# Area-First PARA Framework

_A practical framework for deciding where folders and files belong by choosing the owning Area first, then using Resource, Project, or Normal folders within it. Read before proposing destinations for file or folder organization, especially in Google Drive or another plain file system. Does not contain file-creation approval rules or archive procedures; use `00_Reference/File Creation Rules.md` for those._

_See also: `00_Reference/File Creation Rules.md` (placement, creation, and archive rules) | `00_Reference/Source PDFs/PARA for Google Drive by Jeff Su.pdf` (the original visual framework)_

---

## Core Rule

Choose the Area first. An Area is the ongoing domain that owns the material, such as Health, Housing, Marketing, or Career Development. Once the Area is clear, place the item inside that Area according to how it will be used:

- Put material that supports the whole Area in its Resource folder.
- Put material for a specific time-bound effort in that effort's Project folder.
- Use a Normal folder only when several related folders need a grouping layer.
- Keep files and media inside the relevant Resource, Project, or Normal folder rather than leaving them loose at the Area root.

---

## Routing Decision Tree

1. **Which Area owns this material?** Choose the ongoing domain where you would expect to use it again.
2. **Does it support the entire Area?** Put it in the Area's Resource folder.
3. **Does it belong to a specific time-bound effort?** Put it in that effort's Project folder.
4. **Are many similar folders cluttering the Area?** Group them inside a clearly named Normal folder. Project and Resource folders can sit inside that grouping when useful.
5. **Is the destination still unclear?** Propose the best Area and folder type before writing. Prefer the simplest structure the user can maintain consistently.

---

## Folder Types

### Area Folder

The top-level domain of responsibility. The source framework uses personal Areas such as Health and Housing, and work Areas such as Marketing and Career Development.

### Resource Folder

Use for material that applies across the Area rather than to one project. The source examples use names such as `01 Health | Resources`, `01 Housing | Resources`, and `01 MKT | Resources`.

Examples include claim-form templates and insurance information for Health, apartment-hunting notes for Housing, and budget trackers or creative-brief templates for Marketing.

### Project Folder

Use for a specific effort with its own working files or media. The source examples include a physical checkup, half-marathon preparation, an apartment move, buying a house, a tentpole event, a performance review, and preparation for a sales role.

### Normal Folder

Use as an optional grouping layer when an Area contains many similar folders. For example, Marketing can group individual event projects inside `Tentpole Events`, while Career Development can group yearly reviews inside `Performance Reviews` and role-specific preparation inside `Interviews`.

---

## Worked Examples

| Area | Area-wide Resources | Project folders | Optional Normal folders |
|---|---|---|---|
| Health | Claim-form template, medical history, insurance information | Physical checkup, half-marathon preparation | Usually unnecessary unless the Area becomes crowded |
| Housing | Apartment-hunting spreadsheet, ongoing notes | Apartment move, buying a house | Use only when several related property or move folders need grouping |
| Marketing | Budget tracker, invoice process, creative-brief template | Individual event or campaign folders | Tentpole Events, Scaled Programs |
| Career Development | Review templates or interview resources | Annual performance review, specific role preparation | Performance Reviews, Interviews |

---

## Practical Standard

The framework is a decision aid, not a demand for perfect folder architecture. Apply only the layers that make the system easier to use, and favor a structure the user can maintain consistently.
